تقرير تنفيذي — P6

طبقة ربط الواجهة بالخادم (API Layer)

تحديث كامل لطبقة الاتصال في الواجهة الأمامية لتتكلم مع أوامر البيع الجديدة والإشعارات.

التاريخ: 2026-08-06
المرحلة: Phase 6
الحالة: مكتملة

1. ملخص تنفيذي

قبل هذه المرحلة، كانت الواجهة الأمامية "تتخيل" شكل بيانات أوامر البيع القديمة. تم تحديث طبقة الاتصال بالكامل لتعكس الشكل الفعلي الجديد للخادم: أوامر البيع مع الاعتمادات والتسليمات ورقم الإصدار (للحماية من تعارض التعديلات)، والكميات الموصلة لكل صنف، وقسم الإشعارات الكامل.

الهدف: الواجهة والشاشات التي ستبنى عليها تعتمد على بيانات حقيقية دقيقة — بدون أي "حشو مؤقت".

2. قبل / بعد

قبلبعد
أوامر البيع تُرسَل بكميات موصلة بشكل قديم (deliveredQuantities) لا يطابق الخادم.الكميات الموصلة تُرسَل لكل صنف بشكل صحيح (deliveredItems).
لا يوجد تمثيل للاعتمادات أو التسليمات أو رقم الإصدار.الواجهة تعرف approvals و deliveries و version — وتتعامل معها.
لا توجد دوال للاعتماد/الرفض أو الإشعارات.دوال جديدة: اعتماد، رفض مع سبب، جلب الإشعارات، تعليم كمقروء.
تعديل الطلب عبر PATCH بسيط قد يكتب فوق تعديل زميل.تعديل بـ PUT مع رقم إصدار متوقع — أي نسخة قديمة تُرفض بـ 409.

3. الملفات

  • src/services/api.ts (الواجهة الأمامية) — واجهات البيانات الجديدة + دوال الاتصال الكاملة.
  • إضافة نوع Notification ودوال الإشعارات الجاهزة للاستخدام.
